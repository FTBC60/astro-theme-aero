## 1. 目标与复杂度预算

让已发布文章能展示作者准备的单文件交互工具，例如计算器、算法演示和交互图表。工具随文章进入已有静态构建和附件交付流程。

保留 `output: 'static'`、单一 `notesDir`、显式发布许可与现有路由。首版不新增运行服务、R2、工具发布命令、工具配置目录或前端构建系统；不完整移植旧实验版的依赖扫描与动态资源端点。

这是局部的内容能力扩展，复杂度评估为低至中等。主要成本是发布归属、iframe 生命周期、浏览器隔离及实际静态托管验证，不能仅以生成一个 iframe 判断完成。

## 2. 首版支持范围

| 能力 | 首版建议 |
| --- | --- |
| 作者审查过的 UTF-8 单文件 HTML，内联 CSS、JS | 支持 |
| HTML 内联 SVG、数据和 data URL 图片 | 支持，不额外交付资源 |
| Markdown 显式工具引用、引用式图片写法 | 支持 |
| 同目录文件、笔记根目录内的共享文件 | 支持 |
| 中文、空格路径和部署子目录 | 支持 |
| 开发服务、静态构建、导出及 Publisher 交付 | 纳入验收 |
| iframe 自适应正文宽度、固定默认高度、内容内部滚动 | 高度暂定 480px；桌面/键盘与窄屏布局已验，iPhone Chrome 棋盘和内外滚动获用户实机通过反馈，桌面 Chromium 模拟差异保留；内部布局由工具作者适配 |
| 自动测量内容高度、父子页面消息协议 | 暂不支持 |
| 本地 CSS/JS/图片依赖收集、JS 模块依赖解析 | 暂不支持 |
| CDN 库、远程工具 URL、运行时 API 数据依赖 | 不属于首版支持契约 |
| React/Vue/Vite 项目编译、SSR、数据库或服务器执行 | 不支持 |
| 工具访问博客 DOM、Cookie 或博客同源存储 | 嵌入时不授予 |
| 文件导出下载 | 建议统一开放 `allow-downloads`，支持工具在本地生成文件后导出 |
| 用户选择本地文件并在工具内读取 | 支持标准文件选择器与 File API，不新增上传或文件系统接口 |
| HTML 自声明权限并自动获得授权、逐工具权限配置 | 首版不实现 |
| 表单提交、弹窗、顶层导航、额外浏览器权限 | 不通过主题开放 |
| 跨文章保存工具状态、离开文章继续运行 | 不支持；重新进入时初始化 |
| Obsidian 内直接运行工具 | 不提供；在网站预览中验证 |

“自包含”是作者准备工具时必须满足的使用契约。构建只验证引用类型、文件存在、路径与输出合法性；不通过正则或静态分析声称已经证明任意 JavaScript 无外部依赖。依赖其他资源的工具不受支持，即使某些请求偶然能够成功。

示例工具必须包含 `<meta name="viewport" content="width=device-width, initial-scale=1">`，使用可收缩的内部布局、带标签的输入控件和可见的键盘焦点。主题只约束 iframe 外框，不自动修复工具内部的固定宽度、缩放、焦点陷阱或滚动问题。工具须能在窄屏下完成实际操作，不以容器 `width: 100%` 代替验收。

## 3. 写法与失败规则

```md
![tool: 日期计算器](./日期计算器.html)
```

也支持现有的引用式图片语法：

```md
![tool: 日期计算器][calculator]

[calculator]: ./日期计算器.html
```

建议固定以下规则，不增加一套可配置语法：

- 保留小写、大小写敏感的 `tool:` 前缀，位于图片 alt 开头；前缀后的工具名去除首尾空白后必须非空，用于 iframe 的 `title`。
- 目标必须是相对于当前笔记的本地 `.html` 文件，扩展名判断不区分大小写。不接受站点绝对路径、远程地址、协议相对地址、data/blob URL、查询参数或片段。
- 当前 Wrangler/API 会拒绝字面百分号文件名。首版拟在工具输出相对路径中发现字面 `%` 时明确报错、提示改名；不禁止正常 URL 编码中的 `%20`、`%23`，不自动改名或顺带改变普通附件规则。中文、空格和 `#` 已通过实际部署与路径检查。
- `../` 可以指向 `notesDir` 内的共享资源；按现有规则检查规范化路径和真实路径，拒绝实际越界及符号链接越界。不是一律禁止父目录引用。
- 显式工具引用不合法时，在已发布文章编译阶段报错，报告笔记及目标；不静默退化成图片。
- 普通图片和普通下载链接保留原有处理。`[下载 HTML](./example.html)` 不会自动成为工具；普通图片 alt 以 `tool:` 开头时属于保留写法。
- `cover` 不接受工具语法。原始 HTML iframe 不经过这套工具校验，也不算主题支持的工具入口；不借本次功能清洗或重写全部原始 HTML。
- 继续先筛选发布许可。仅被未发布笔记引用的工具不进入文章附件计划，其中无效工具引用也不参与正文校验；原有 Frontmatter 语法错误规则不变。

## 4. 隔离模型及明确限制

生成的 iframe 固定包含：

```html
<iframe
  src="带部署前缀的文章附件地址"
  title="日期计算器"
  sandbox="allow-scripts allow-downloads"
  loading="lazy"
  referrerpolicy="no-referrer"
  class="aero-embedded-tool"
></iframe>
```

**首版推荐固定权限为 `allow-scripts allow-downloads`。** 所有通过显式工具写法嵌入、经作者审查的工具采用同一策略，允许脚本和文件导出；不提供任意 sandbox 字符串、权限配置开关或逐工具差异。不添加 `allow-same-origin`、顶层导航、弹窗、模态对话框或表单提交权限，也不额外委派摄像头、麦克风等能力。属性值必须进行 HTML 转义，工具 `src` 使用与正文图片一致的带部署前缀的稳定地址，避免客户端切页时相对旧页面解析。

工具在 iframe 中处于不透明来源环境；同源 HTML 同时获得 `allow-scripts` 与 `allow-same-origin` 可能逃离 iframe sandbox，参见 [HTML 标准的 sandbox 说明](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)。计算按钮应使用 `type="button"`，结果显示在文档中，不依赖 alert、表单提交或持久存储。

选择统一双权限是当前可信作者模型下的工程取舍：2048 已有 JSON 导出需求，日期计算器、数据图表也可能导出结果；固定策略不需增加权限清单解析、Markdown 扩展或配置继承。它的代价是无需下载的工具也获得下载能力，不能称为逐工具最小权限。

`allow-downloads` 并非“只允许 JSON”或“只允许点击后下载”。[MDN 的 sandbox 说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox)指出，它也覆盖脚本未经用户交互发起的下载；浏览器仍可能施加自身的下载限制。主题不把这个 token 描述为格式白名单或用户手势强制机制。首版要求作者工具通过明确的导出按钮触发下载，避免加载即下载和循环下载；这属于工具实现与审查要求，不是 iframe 自动提供的保证。

### 工具声明与主题授权

首版不读取 HTML 内的权限声明，不自动合并工具请求到 iframe。工具可以在说明文档中写出需要脚本、下载等能力，供作者判断是否符合固定契约；声明本身不构成授权。

未来若出现确需区分的场景，可讨论由文章作者显式选择“脚本”或“脚本＋下载”两种预设，或一个下载布尔选项；不直接开放任意 sandbox token。即使届时支持机器可读的工具声明，也只能在主题允许集合与作者显式授权范围内生效；不支持的要求应报告错误，而非自动开放同源或其他能力。这些机制不纳入首版实现。

### 文件导入、导出与存储要求

- 导入使用 `<input type="file">` 与 File API 读取用户选择的文件，不需要 `allow-forms`，也不建立上传接口、后台或本地路径读取权限。参见 [File API 文件选择说明](https://developer.mozilla.org/en-US/docs/Web/API/File_API/Using_files_from_web_applications)。
- 导出的文件由工具在浏览器中生成，例如 JSON Blob 与下载链接；清理临时对象 URL，不以直接写入某个磁盘路径或覆盖源笔记附件作为能力目标。下载保存位置及重复下载处理由浏览器与用户控制。
- 文件的大小上限、JSON 解析与业务结构校验属于工具实现职责。当前 2048 使用 64 KiB 上限，错误导入应保留现有对局；这是样本规则，不强加给全部工具。`accept` 只作为选择提示，不能代替内容校验。
- 不依赖博客 Cookie、localStorage 或 IndexedDB。存储不可用时工具仍须启动、操作和导出；离开后通过再次选择导出的文件恢复，不承诺自动保存或跨页状态。
- JSON 导入、下载能力不等于获准联网；自包含契约不包含上传或远程 API。sandbox 本身也不负责禁止所有联网，需通过工具审查和实际请求记录核对。

**信任前提：首版只承载作者审查过的工具。** iframe sandbox 不等于禁止联网，也不是 CPU、内存或防死循环的执行配额。主题不承诺安全运行恶意或未知来源程序。

**直接访问限制：** HTML 文件仍由站点托管，单独访问文件 URL 时不会自动继承 iframe 属性。首版不宣称直接访问也被隔离，不提供“在新窗口打开工具”的入口。HTML 标准也提醒，同源托管的敌对内容可能通过直接访问绕过 iframe 层的约束。

**信任取舍：** 采用“同源托管、只发布作者审查过的工具”这一前提，直接访问时没有 iframe sandbox；响应级 CSP 暂作后续增强。这项取舍已进入采用的 ADR-0014，并同步中英文作者说明。准确表述为“通过主题生成的 iframe 嵌入时提供隔离”，不能表述为“工具始终被隔离”。阶段 A 直接访问测试也确认正常来源存储可用，不把设计采用或部分验收当作完整安全隔离证明。

若后续需求变为承载不可信工具，需重新设计独立来源或响应级隔离后再扩大范围。响应级 `Content-Security-Policy: sandbox allow-scripts allow-downloads` 可作为另一个方案，权限应与嵌入策略协调，但不能用 HTML `<meta>` 等价替代，参见 [CSP sandbox 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/sandbox)。Cloudflare 静态托管支持 [`_headers`](https://developers.cloudflare.com/workers/static-assets/headers/)，因此响应头本身不要求恢复 SSR；不过精确 URL 匹配、HTML 路径规范化、已有头规则合并和其他托管平台都需要额外设计与验收，本草案不自动加入这部分实现。

## 5. 发布归属与撤稿

工具是文章实际引用的可执行附件，识别为工具的条件与普通附件不同，底层文件交付继续共用现有附件计划。

- 同目录 HTML 保留现有相对输出结构；共享 HTML 沿用当前文章 `_attachments/` 的输出规则，不另建全站 `/tools/` 目录。
- 同一文章对同一源文件和同一输出目标的重复引用在计划中去重。不同文章引用同一工具时，各自生成文章所属副本，不引入跨文章共享资源索引。
- 某篇文章撤稿时，下一次成功构建、部署移除其页面和所属工具副本，其他文章的副本继续有效。
- 工具仍被同一篇文章的普通附件链接引用时，仅删除 iframe 不代表文件不再被引用；沿用实际引用规则。
- 原始 MD 不作为工具依赖交付。不遍历或整目录发布 Vault，不因 HTML 存在而自动公开它。
- 上述发布范围只约束从笔记入口进入产物的文件；作者另放在 `public/` 的资源仍遵循其原有发布规则，不自动受文章撤稿管理。
- 静态撤稿以成功构建和完整站点部署为准，不增加请求时授权或立即撤稿保证，无法撤回访客已有的缓存和下载副本。

### 源路径、输出路径、浏览器 URL 与用户存档

推荐维持“一篇日记和它的附件放在同一文件夹”的组织方式：

```text
notesDir/
└── 2026-11-03/
    ├── 2026-11-03.md
    ├── 照片.png
    └── 2048.html
```

MD 中继续写 `![tool: 2048 小游戏](./2048.html)`；示例假设 Frontmatter 显式设置 `slug: "2026-11-03"`。slug 是文章 ID，与源文件所在目录是两个概念；省略 slug 时仍按现有相对笔记路径生成 ID，不自动消除同名文件夹和文件造成的重复路径。

| 层次 | 示例 | 谁负责 |
| --- | --- | --- |
| Markdown 源引用 | `./2048.html` | 作者使用相对笔记的写法，不填写部署域名 |
| 构建读取的文件 | `notesDir/2026-11-03/2048.html` | 相对于当前 MD 定位，检查真实路径仍在 notesDir 内；Publisher 实际从验证后的笔记快照读取 |
| 生成站点中的文件 | `dist/posts/2026-11-03/2048.html` | 既有附件计划与复制流程；Publisher 的隔离站点目录等价 |
| 根路径部署的 iframe src | `/posts/2026-11-03/2048.html` | 编译器根据文章 ID 生成站点内地址 |
| `/blog/` 部署的 iframe src | `/blog/posts/2026-11-03/2048.html` | 编译器添加部署前缀，不在输出目录额外复制一份 blog |
| 访客导出的 JSON | 浏览器下载位置中的 `2048_分数.json` | 访客保存并通过文件选择器重新导入，不加入站点附件计划 |

iframe 不原样使用 Markdown 的 `./2048.html`，也不暴露 NAS/Windows 的源文件绝对路径。复用已有 `resolveNoteAsset` 和 `publishedAssetUrl`：只在文件系统解析时解码路径，再按 URL 路径段编码并进行 HTML 属性转义，不把整个 URL 一次编码，不对已有 `%20` 重复编码。中文、空格和 `#` 按现有附件引用规则处理；本次实测发现的字面 `%` 工具输出路径限制见第 3 节。

共享工具例如 `../共享工具/计算器.html` 仍输出到当前文章的 `_attachments/共享工具/` 内，生成对应的带部署前缀 URL。文章使用自定义 slug、移动源文件夹或切换笔记挂载位置时，由编译器重新计算映射，作者不手写发布路径。

工具 HTML 本身按原文件字节交付，不编译其中脚本、不注入 NAS 路径、不扫描或重写资源引用；内联脚本、UTF-8、doctype、data URL 在 dev 与 build 中应保持一致。开发服务只响应当前附件计划中的文件，不因为支持 HTML 就放开整个笔记目录读取。

`publish: true` 继续先决定 MD 是否进入编译与附件收集；HTML 不另设发布开关。未发布笔记独占引用的 HTML、仅存在于同目录的 HTML 或 JSON 均不会因此自动公开。JSON 导入通过用户选择完成，不使用 `fetch('./存档.json')` 自动读取日记同目录文件，也不增加单文件工具的依赖扫描。

## 7. 分阶段实施与验收

### A. 前置技术验证，再收敛契约

使用当前 2048 单文件样本，在推荐的 `sandbox="allow-scripts allow-downloads"` 下验证输入、按钮、文件导入、JSON 下载及窄屏显示。若需要联网、存储或另外的权限，先调整工具或重新讨论范围，不能在实现中默默开放权限。样本已有的独立 Chrome 测试记录只作为历史依据，主题接入、目标手机浏览器与 Cloudflare 路由仍需分别验证。

在正式接入编译模块之前，用独立临时样本完成两组验证；样本与浏览器步骤放在开发测试区域，不改变正式主题架构，也不将样本混入当前线上站点：

1. **无工具脚本的页面切换。** 使用当前 Astro 7.3.8 和现有 ClientRouter 配置，先只生成带 `loading="lazy"` 和固定双权限 sandbox 的 iframe；覆盖首次访问、站内进入、离开再返回、历史前进/后退，以及 iframe 初始位于屏幕外、滚动进入视口。至少覆盖桌面 Chromium 与手机使用的浏览器内核，明确尚未覆盖的环境。仅在出现可复现异常时考虑最小客户端补丁，不为了补丁复用而开放权限或实现持久会话。
2. **静态 HTML 交付与路由。** 先用固定版本 Wrangler 的本地静态资源服务验证最小产物，随后在隔离的 Cloudflare 测试站点复验；本地结果不代替真实托管结果。采用当前 `wrangler.json` 的 `html_handling: 'force-trailing-slash'` 与 `not_found_handling: 'none'`，不照搬默认 `auto-trailing-slash` 的示例，不为工具改变全站 HTML 处理方式。

当前 [Cloudflare HTML 处理文档](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/#force-trailing-slashes)列明，在 `force-trailing-slash` 下，`/file.html` 以 307 重定向到 `/file/`。这本身不等于工具无法加载，也不要求生成的 iframe `src` 与重定向后的 URL 字面相同。暂定继续生成带部署前缀的实际 `.html` 附件地址，让托管平台处理规范化，以保留普通静态主机兼容性；前置验证不通过时再修订。

路由验证至少覆盖：

- 同目录及共享附件输出，中文/空格路径、根路径与 `/blog/` 前缀；分别记录初始 URL、每次重定向及最终 URL、内容类型和工具内容标识。
- `.html`、无扩展名、尾斜杠及服务实际接受的其他别名。更新工具后比较内容；删除后重新请求所有已记录地址并跟随重定向，确认均不再返回旧工具正文，不能单凭 200 或某个地址的 404 判断。
- 文件层冲突与规范化后 URL 行为分别验证。阶段 A 已验证 `tool.html` 与 `tool/index.html` 并存时，当前 Cloudflare 让完整 `.html` 地址返回平面文件，而尾斜杠地址返回目录入口，不能一律判定冲突。保留完整附件 URL 和现有 `assetPlan` 文件冲突检查，暂不新增通用路由检测；后续为这组已知行为补回归，若出现其他错误映射再做局部处理。
- 工具不依赖相对加载资源，也不假定最终 URL 必须保留 `.html`，因此路径规范化不会成为恢复依赖扫描或重写工具内容的理由。

阶段 A 已生成可复现样本与结果记录：Chrome 和 Cloudflare 的基础链路通过，工具字面百分号文件名被当前上传链路拒绝，WebKit 长页和 Chrome 触屏模拟仍未通过。两个云端临时站点均已删除。完整实验、版本、失败对照和未覆盖项见[阶段 A 记录](../../tools/test/validation-docs/embedded-tools-phase-a-2026-11-03.md)，不能将本阶段标为完整移动兼容性通过。
