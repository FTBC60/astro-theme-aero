# 播放会话与 DOM 接入

2026-10-31 建立，2026-11-11 更新（America/Los_Angeles）。本模块承接 [ADR-0006](../adr/0006-runtime-static-playlist.md) 的静态歌单和跨页音频实例，以及 [ADR-0017](../adr/0017-blob-playback-and-media-session.md) 的 Blob 播放、单首预取和 Media Session 决策。阶段讨论与历史检查见[开发方案与实施记录](music-player-development-plan.md)。

## 模块职责

- `src/scripts/playback-session.ts` 的 `createPlaybackSession` 管理歌单请求、超时与重试、当前 Blob、单首预取候选、播放意图、模式、进度及异步结果。它接受音频、网络和计时依赖，不查找或修改 DOM，也不依赖 `window`、页面地址或界面语言。
- `src/scripts/music.ts` 负责读取播放器节点，提供浏览器音频 adapter，将播放与进度条输入转发给会话，并根据只读快照与通知更新文字、图标、加载圈、封面、错误和无障碍属性。Media Session 动作转发、元数据和真实播放状态同步位于这一层。标题溢出留在这一层；歌单开关、焦点、触摸判定及浮层定位由[歌单浮层模块](playlist-panel.md)统一接入，选曲意图再交给会话。
- `src/scripts/playlist.ts` 校验 JSON，并根据歌单 URL 和显式部署 base 解析媒体 URL；解析过程可直接在 Node 测试中运行。

会话对外提供 `getSnapshot`、`refresh`、`play`、`pause`、`togglePlayback`、`retry`、`select`、`skip`、`seek`、`seekTo`、`cycleMode` 和 `dispose`。状态变化通过 `onChange(snapshot, notice)` 通知接入层。通知表达“已选择”“播放失败”等含义，界面层使用现有中英文文案。快照及曲目不可由调用方修改。

## 既有行为

- 首次加载及手动刷新只更新静态歌单，不自动播放，也不创建周期轮询。
- 刷新后当前音频 URL 仍存在时，保留同一个音频源、进度和播放/暂停状态；允许列表重排或修改歌曲名称及封面。
- 移除当前歌曲时停止并选中第一首可用歌曲，等待用户播放；清空列表时停止并清除音频源。
- 请求、JSON 或数据校验失败时保留最后可用歌单和当前播放。首次失败可重试；空数组是正常加载结果。
- 顺序播放在最后一首结束时停止，列表循环回到第一首，单曲循环归零重播。上一首/下一首保留暂停状态，点击歌单曲目开始播放并收起浮层。
- 超时中止请求；即使依赖延迟返回，也不能将旧结果覆盖到后续刷新结果上。

## Blob、就绪状态与媒体控制

首次播放完整下载音频，创建临时 Blob URL 并初始化音频元素。会话持有当前资源和最多一首候选，当前曲实际播放后立即预取下一首。手动切换到不同歌曲时立即释放旧源，复用有效候选或下载最新目标。同曲重新选择、暂停恢复和单曲循环复用当前资源及相应进度。

`loaded` 只记录原始音频 URL 和 Blob URL，`trackStatus` 统一表达加载阶段及就绪。`canplay` 在资源匹配且具备播放条件时进入 `ready`，`currentReady()` 同时检查资源存在与当前曲目匹配。`wantPlaying` 保存用户意图，实际播放状态读取音频元素。歌单请求的 `loadStatus` 与歌曲加载的 `trackStatus` 分别描述各自任务。

网页与系统控件共用 `play()`、`pause()`、`skip()` 和按秒跳转的 `seekTo()`。快照中的 `loadedTrack` 仅在当前资源就绪且音频源匹配时输出，供 Media Session 更新歌曲信息。位置同步读取音频元素真实时间、时长和倍速，动作与元数据分别按能力和内容变化更新。

下载和初始化期间显示封面加载圈并禁用进度调节，就绪后封面约 200ms 淡入。Safari 播放授权被拒绝时保留就绪资源，等待用户点击。歌曲加载错误使用 `trackError`，歌名栏显示“加载失败”，底部反馈与“重新加载”入口对应实际失败任务。返回前台后继续有效下载，已失败任务等待手动重试。

## 异步结果与生命周期

每次播放都有内部请求序号。暂停、切歌、移除当前歌曲或销毁会话会使旧请求失效；旧 `play()` Promise 的成功或失败不再改变当前状态与通知。当前请求的真实错误仍显示失败反馈，浏览器正常的 `AbortError` 不显示为播放故障。

音频下载使用取消控制器与候选任务身份核对，确保旧响应体无法覆盖最新选曲。释放资源时解除音频源并撤销 Blob URL，候选失效时取消在途请求并清除引用。

会话随持久化的播放器节点存活。`astro:page-load` 后仍是原节点时直接复用，不重新获取歌单、不重设音频 `src`。只有节点被替换或移除时才释放旧会话，中止网络、清除超时、取消音频监听、停止音频并撤销 Blob URL。DOM 接入也释放事件、观察器及 Media Session 状态，并调用浮层模块的统一释放入口。浮层内部协调定位与触摸的导航暂停、祖先重接入和清理，原手势与布局规则保持原样。

2026-11-11 的 Blob、即时切歌及就绪状态精简检查覆盖同曲复用、预取消费、下载期间暂停、播放授权恢复、旧 URL 撤销及过期结果失效。结果和第 5 阶段整体验收范围见 [ADR-0017](../adr/0017-blob-playback-and-media-session.md)。原型与详细设备记录位于本地 `tools/test/prototypes/music-player/`，该目录沿用现有忽略规则。
