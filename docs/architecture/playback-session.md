# 播放会话与 DOM 接入

2026-10-31（America/Los_Angeles）。本改进在 ADR-0006 的静态歌单和跨页音频实例决策内，集中播放规则并建立可验证的 interface。

## 模块职责

- `src/scripts/playback-session.ts` 的 `createPlaybackSession` 管理歌单请求、超时与重试、当前曲目、播放模式、进度操作及异步播放结果。它接受音频、网络和计时依赖，不查找或修改 DOM，也不依赖 `window`、页面地址或界面语言。
- `src/scripts/music.ts` 负责读取播放器节点，提供浏览器音频 adapter，将播放与进度条输入转发给会话，并根据只读快照与通知更新文字、图标、列表和无障碍属性。标题溢出留在这一层；歌单开关、焦点、触摸判定及浮层定位由[歌单浮层模块](playlist-panel.md)统一接入，选曲意图再交给会话。
- `src/scripts/playlist.ts` 校验 JSON，并根据歌单 URL 和显式部署 base 解析媒体 URL；解析过程可直接在 Node 测试中运行。

会话对外提供 `getSnapshot`、`refresh`、`togglePlayback`、`select`、`skip`、`seek`、`cycleMode` 和 `dispose`。状态变化通过 `onChange(snapshot, notice)` 通知接入层；通知表达“已选择”“播放失败”等含义，界面层使用现有中英文文案。快照及曲目不可由调用方修改。

## 既有行为

- 首次加载及手动刷新只更新静态歌单，不自动播放，也不创建周期轮询。
- 刷新后当前音频 URL 仍存在时，保留同一个音频源、进度和播放/暂停状态；允许列表重排或修改歌曲名称及封面。
- 移除当前歌曲时停止并选中第一首可用歌曲，等待用户播放；清空列表时停止并清除音频源。
- 请求、JSON 或数据校验失败时保留最后可用歌单和当前播放。首次失败可重试；空数组是正常加载结果。
- 顺序播放在最后一首结束时停止，列表循环回到第一首，单曲循环归零重播。上一首/下一首保留暂停状态，点击歌单曲目开始播放并收起浮层。
- 超时中止请求；即使依赖延迟返回，也不能将旧结果覆盖到后续刷新结果上。

## 异步结果与生命周期

每次播放都有内部请求序号。暂停、切歌、移除当前歌曲或销毁会话会使旧请求失效；旧 `play()` Promise 的成功或失败不再改变当前状态与通知。当前请求的真实错误仍显示失败反馈，浏览器正常的 `AbortError` 不显示为播放故障。

会话随持久化的播放器节点存活。`astro:page-load` 后仍是原节点时直接复用，不重新获取歌单、不重设音频 `src`。只有节点被替换或移除时才释放旧会话：中止网络、清除超时、取消音频监听并停止音频。DOM 接入也释放事件及观察器，并调用浮层模块的统一释放入口；浮层内部协调定位与触摸的导航暂停、祖先重接入和清理，原手势与布局规则保持原样。

## 验证

`npm run test:playlist` 同时运行受控音频、网络及计时依赖下的会话测试和既有触摸回归。覆盖 URL/base、加载与空列表、刷新保留/移除规则、四类失败、超时及迟到响应、旧播放结果、三种模式、进度及生命周期清理。

本地浏览器使用真实音频及隔离的 `/blog/` 静态构建验证播放/暂停、选曲、歌单重排保留进度、HTTP 失败保留播放、移除和清空停止，以及站内导航续播。390×844 窄屏验证侧栏、20 首歌单的滚动与选曲、模式切换和键盘关闭；该检查使用鼠标/键盘，不等同于物理手机的触摸手感验收。测试歌单由本地验证服务提供，原 `public/audio/playlist.json` 保留。

播放会话提取时的本地验收：24 项会话测试、22 项触摸测试、18 项内容/Vault 测试、7 项发布资源测试及 11 项 Publisher 测试通过。Windows 上同时运行工作区 dev 服务器与隔离构建时，文件监听曾造成目录 rename 的 EPERM；停止验证用服务器后串行复验通过，未因此修改 Publisher 流程。NAS 与手机实机复验另行记录。

2026-10-31 浮层协作收整后，新增 11 项浮层测试，原 22 项触摸测试改为经过完整浮层入口执行；播放会话 24 项继续通过。交互约定、导航生命周期及新增真实浏览器验证范围见[歌单浮层与播放器接入](playlist-panel.md)。
