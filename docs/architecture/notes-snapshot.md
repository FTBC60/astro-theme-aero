# 笔记快照与 Publisher 接入

2026-10-31（America/Los_Angeles）。在 [ADR-0008](../adr/0008-isolated-scheduled-publisher.md) 的只读输入与隔离构建约定内，将笔记快照的复制、校验、有限重试和失败清理集中到同一模块。文章扫描、发布许可、互链和附件规则不在本次改动范围。

## 职责与 interface

`tools/lib/notes-snapshot.mjs` 的 `createNotesSnapshot({ source, stage, signal, onRetry })` 接受可读的笔记根目录和已存在、由本任务独占的构建目录，返回 `{ directory, digest }`。成功结果表示副本与本次读取的源指纹一致，可以继续构建；模块不获取发布锁，也不运行 Astro 或上传。

模块固定使用构建目录下的 `.notes`，内部负责清除旧副本、复制整个笔记输入、比较源与副本指纹，以及失败时清理未完成的副本。源与工作目录不得重叠。清理使用 `tools/lib/paths.mjs` 的 `removeWithin`，先核对绝对路径和真实路径，再删除；不允许清理父目录本身或通过链接越界。

Publisher 仅消费返回的目录和指纹：根据目录生成隔离副本的 `notesDir` 配置，将指纹写入成功结果。Publisher 继续管理发布锁、整个任务目录、状态与日志、构建检查、产物检查和部署。快照模块失败时，Publisher 记录失败并清理整个任务目录，不进入检查、构建或上传，也不替换 `last-success.json`。

`copyNotes` 与 `fingerprint` 的文件操作实现继续复用，不为每个机械动作增加 adapter。完整树复制可作为可选依赖传入快照函数，测试在真实复制后的确定时点制造变化或失败；Publisher 的可选快照依赖用于在相同快照 interface 上验证发布失败阻断。生产调用使用默认实现。

## 校验、重试与取消

每次尝试依次执行：清理上次副本 → 读取源指纹 → 复制 → 比较副本指纹 → 副本一致时再次比较源指纹。任何指纹不一致都丢弃该副本并重新尝试，总计最多三次，第三次仍可成功。前两次不一致时调用同步 `onRetry` 通知 Publisher 记录日志，持续不一致则报错。

权限、文件缺失、越界符号链接等读取或复制错误直接失败，不作为内容变化重试。取消信号在文件操作之间检查；正在执行的文件操作完成后才能响应取消，随后清理副本。失败清理不受已取消的信号阻止；清理自身也失败时，同时报告原始错误和清理错误，不尝试越界删除。

成功后副本随 Publisher 的工作目录存活，由 Publisher 最终释放。读取和复制均不会写入原始笔记。指纹包含文件内容、相对路径、空目录及笔记根内链接的相对目标；允许的链接在副本内重定位，越界链接和特殊文件继续拒绝。

这仍不是文件系统原子快照，也不保证源目录在最后一次核对后不再变化。发布锁只协调共享数据目录的发布任务，不锁定笔记编辑器或同步器。编辑和同步完成后再发布的运行建议保持不变。

## 验证

`npm run test:publisher` 包含 `tools/test/notes-snapshot.test.mjs` 的完整快照行为测试，以及 `tools/test/publisher.test.mjs` 的发布接入回归。

快照测试使用真实临时文件，验证稳定/空输入、源变化与副本不一致后的重试、第三次成功和三次耗尽、旧文件清除、I/O 错误、取消、中文路径、链接重定位、目录重叠拒绝与失败清理。并发变化通过受控的整树复制依赖触发，不使用 sleep 或持续写入争抢时序。

Publisher 接入测试验证重试后的目录与指纹进入后续流程，持续变化、I/O 错误和取消时不运行任何检查、构建或上传命令，并保留上次成功记录及已检查的站点。原有真实隔离构建、内容/Vault 和资源交付回归继续验证调用路径。

2026-10-31 本地验证：14 项快照行为、14 项 Publisher、18 项内容/Vault 和 7 项发布资源测试通过，共 53 项。真实隔离构建覆盖相对与外部绝对笔记目录，以及附件更新和撤稿清理；发布流程测试中的上传使用替身，本轮未执行真实上传。

发布工具属于 Docker 镜像，本次更新需要重建并重新创建 NAS 发布容器。本文的本地测试不代替 NAS、Linux 调度、只读挂载或线上发布验收。
