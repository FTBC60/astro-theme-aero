## 1. 目标与技术路线

本轮目标包括修复歌曲进度跳转、提供 Aero 风格加载反馈、减少连续切歌产生的无效下载，以及接入浏览器和系统媒体控制。

采用完整下载音频为 Blob 的路线。用户触发播放后，播放器下载完整音频，创建临时 Blob URL，等待音频具备播放条件，再根据用户最新播放意图启动或保持暂停。浏览器负责对完整音频进行定位、读取和解码。

网页进度条和 Media Session 共用播放会话中的操作。音频实例、Blob 资源、下载任务及进度跟随现有持久播放器跨页保留。

播放器会话持有当前歌曲及最多一首预取候选。当前歌曲使用临时 Blob URL，候选以已完成的 Blob 或在途下载任务持有，成为实际加载歌曲时创建播放 URL。原始音频 URL 用于识别歌曲、比较歌单更新、复用资源及重新下载。

### 1.1 已有研究依据

以下是此前研究阶段的结果，编写本文时未重新执行这些实验。

- 线上《海中都市》《暖かな時間》的范围请求返回 `200` 整文件响应，缺少 `Content-Range` 和 `Accept-Ranges`。
- 桌面浏览器中，点击进度条后音频回到开头。直接设置 `currentTime = 60` 也能复现。
- 对同一份《海中都市》WAV 数据，模拟忽略 Range 时，可跳转范围为 `[0, 0]`，请求定位至 60 秒后回到 0 秒。模拟正确的 `206` 范围响应时，可跳转范围覆盖全曲，并成功定位至 60 秒。
- 将相同音频完整下载为 Blob 后，桌面浏览器可以定位至 60 秒。
- iPhone Safari 已验证 Blob 前台播放、跳转、锁屏播放，以及当前曲持续播放期间的后台预取和就绪后自动衔接。首次播放可能需要下载完成后再次点击。预取未完成且当前曲已结束时，长时间后台读取仍有中断样本。

Cloudflare 官方记录了 Workers Static Assets 对 Range 请求返回整文件的行为。当前单个静态资源大小上限为 25 MiB。该文件大小上限与浏览器实际内存占用需要分别看待，资源验收应覆盖引用清理和多轮切歌后的资源趋势。[Range 限制](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/#range-requests) · [静态资源限制](https://developers.cloudflare.com/workers/platform/limits/#static-assets)

## 2. 下载触发时机

各个选曲入口立即处理最新目标，下载任务按歌曲地址复用或取消。

| 操作 | 下载时机 |
| --- | --- |
| 用户首次点击播放 | 立即开始 |
| 网页上一首、下一首 | 立即复用有效候选或开始下载 |
| 播放列表选曲 | 立即复用有效候选或开始下载 |
| Media Session 上一首、下一首 | 立即复用有效候选或开始下载 |
| 当前歌曲实际开始播放 | 按现有播放模式确定下一首并立即预取 |
| 当前歌曲自然结束后加载下一首 | 立即复用已就绪候选，或等待同一在途任务，缺少有效候选时立即下载 |
| 用户重试失败的加载 | 立即开始 |
| 恢复当前已加载歌曲 | 复用现有 Blob |
| 单曲循环 | 复用现有 Blob，回到曲首播放 |

首次进入页面时沿用现有歌单读取流程，音频下载由播放操作触发。

## 3. 目标歌曲、已加载歌曲与播放意图

在现有播放会话中分别记录以下事实。

- 目标歌曲代表用户最新选中的曲目，网页标题立即反映该选择。
- 已加载歌曲代表音频元素当前持有的资源，使用原始音频 URL 识别。
- 预取候选代表当前播放模式下预计的下一首，记录其原始音频 URL、在途任务或完整 Blob。
- 播放意图代表用户希望播放或暂停，可以在等待和下载期间改变。
- 实际播放状态来源于音频元素及其事件。
- 下载任务记录取消控制器并核对任务身份，播放请求使用序号判定结果有效性。

这些信息用于扩展现有会话，具体表示方式在实现时沿用已有代码结构。

### 3.1 切歌时的资源替换

以 A 正在播放、用户选择 B 为例。

1. 立即暂停 A，网页显示 B 的标题，封面区域进入循环加载状态，进度归零并暂停调节。
2. 立即解除 A 的音频源、撤销旧播放 URL 并释放旧 Blob，取消与 B 无关的下载。
3. 按原始音频 URL 查找 B 的候选，完整时直接消费，在途时继续等待同一任务，缺少有效候选时立即下载。
4. B 完整下载后创建并挂载新的播放 URL，初始化成功后进入就绪状态，按最新播放意图播放或保持暂停。自然切歌立即执行资源切换，单曲循环及顺序播放末曲停止沿用当前资源。

连续切歌以最新目标为计算起点。`A → B → C → A` 最终选中 A，通过有效候选或重新下载从曲首开始。重新选择当前已就绪歌曲、暂停恢复及单曲循环复用当前资源。

### 3.2 并发与取消

- 每次目标变化时，取消无关下载，并使旧播放请求编号失效。与新目标一致的候选下载继续复用。
- 下载完成、创建 Blob URL、初始化完成及启动播放等异步边界都检查任务是否仍然有效。
- 过期任务只能清理自身资源，避免覆盖标题、封面、错误、进度或实际音频源。
- 下载期间重复点击播放更新播放意图，复用当前任务。
- 下载期间点击暂停后，当前有效下载继续进行，完成后进入就绪暂停状态。
- 已取消任务按正常生命周期退出，用户可见失败反馈仅对应当前有效任务。

### 3.3 歌单与跨页生命周期

- 网页上一首、下一首和列表选曲延续现有入口的播放意图规则。
- 顺序播放、列表循环、单曲循环沿用已有语义。
- 歌单刷新后，原始音频 URL 仍有效时保留对应资源与播放进度。
- 当前目标或已加载歌曲被移除时，核对最新歌单，取消失效任务并释放失效资源。空列表进入播放器现有禁用状态。
- Astro 客户端切页和历史导航继续使用持久播放器实例，保留当前 Blob、有效任务及播放意图。
- 播放器实际销毁时，取消计时及请求，停止音频，解除资源引用，撤销 Blob URL，并清理监听器和媒体会话。

### 3.4 下一首预取

- 在当前歌曲实际开始播放后，复用现有播放模式和下一首选择规则确定候选，立即开始预取。
- 单曲循环复用当前资源。顺序播放到列表末尾时，按现有结束行为处理。
- 当前歌曲之外最多保留一首有效候选。候选变化时，取消无关请求并释放已失效的候选 Blob。
- 候选保持为 Blob，实际切入该曲目时再创建播放 URL。下载和消费均按原始音频 URL 校验身份。
- 用户暂停后，有效在途下载可以完成并保留就绪资源，播放状态跟随最新意图。
- 预取失败记录为候选失败，当前歌曲继续正常播放。该候选成为目标时，进入目标曲目的加载或失败处理流程。
- 歌单或播放模式变化时重新核对候选，复用仍有效的原始音频 URL 对应资源，取消失效任务。候选随持久播放器跨页保留。

### 3.5 自然切歌时预取尚未就绪

1. 当前歌曲结束后立即选中下一首，歌名栏显示目标歌曲，进度归零，封面区域显示加载圈。
2. 有效预取仍在进行时继续等待同一任务。候选已经失败或缺失时，立即发起该目标的有效下载。
3. 完整下载并具备播放条件后，将加载圈渐变为封面，并依据最新播放意图播放或保持暂停。
4. 等待期间发生目标变化、暂停或播放器销毁时，按相应生命周期更新任务及播放意图。
5. 有效下载失败时进入第 5 节的失败展示与重试流程。完成、失败及恢复均依据实际任务和媒体事件判断。

## 4. Aero 加载与封面交互

在封面区域使用 7.css 的 Windows 7 Aero 循环加载圈，按组件范围引入其样式、资源及相应许可信息。[7.css Spinner 示例](https://khang-nd.github.io/7.css/#spinner)

加载区域底色参考 `public/image/music-cover.svg` 中的 `background` 深蓝渐变，沿用 Windows Media Player 风格。配色参考由中心至边缘的 `#3e7bad`、`#22547e`、`#102d4d`、`#071a32`，加载圈位于该背景中央。底层与歌曲封面共用同一显示区域及边界。

| 状态 | 封面区域 | 歌名栏与进度 |
| --- | --- | --- |
| 下载中 | 持续显示同一个加载圈 | 显示目标标题，进度保持零 |
| 自然切歌后等待在途预取 | 深蓝背景上持续显示加载圈 | 显示下一首标题，进度保持零 |
| 音频初始化中 | 持续显示加载圈 | 显示目标标题，进度保持零 |
| 已就绪且有播放意图 | 加载圈淡出，封面淡入 | 尝试播放，进度跟随实际播放推进 |
| 已就绪且为暂停意图 | 显示封面 | 保持暂停，允许用户播放和调节进度 |
| Safari 播放授权被拒绝 | 显示已就绪歌曲的封面 | 保持目标歌曲标题，播放按钮显示播放图标，等待用户操作 |
| 当前歌曲加载失败 | 停止加载圈 | 歌名栏只显示“加载失败”，进度归零并暂停调节 |

加载完成的判定为 Blob 下载完成且音频具备播放条件。封面以约 200ms 的短过渡切换，播放启动与动画并行。

封面从加载圈切换出现，即表示该曲已经具备播放条件。就绪及播放状态通过封面、歌曲标题和播放按钮呈现。Safari 播放授权被拒绝时保持相同的就绪暂停外观，用户点击播放后复用已加载资源。

封面图片在音频下载期间准备。封面读取失败时使用默认封面，音频继续进入就绪状态。封面的异步结果也需要核对最新目标，避免旧封面覆盖新曲目。

等待阶段统一使用深蓝背景上的循环加载圈表达，下载读取采用完整 Blob 流程。歌曲进度条始终表示播放位置，错误原因按第 5 节显示。

## 5. 错误展示与重新加载

### 5.1 当前歌曲加载失败

- 歌名栏仅显示“加载失败”。
- 播放列表底部显示失败歌曲名称和可理解的错误原因。
- 原“刷新歌单”按钮文字改为“重新加载”，操作目标改为当前失败歌曲。
- 点击后立即重试该歌曲。重试期间显示目标歌曲标题和封面加载圈，清除上一轮错误，底部按钮进入加载中的禁用状态。
- 成功后恢复正常界面及“刷新歌单”按钮行为。
- 用户选择另一首时清除旧歌曲的错误，并切换至新目标的加载流程。

错误区域位于播放列表底部的正常文档流中，长文案允许换行撑开。列表沿用当前开合状态，展开后可查看详情及重试入口。

### 5.2 歌单读取失败

- 在播放列表底部显示歌单读取失败原因。
- “重新加载”重试歌单请求。
- 已有歌曲仍然有效并可播放时，歌名栏继续显示当前歌曲标题。
- 首次读取失败且缺少可用歌曲时，歌名栏显示“加载失败”。
- 按钮的恢复目标由当前展示的错误类别确定，并与旁边的错误说明对应同一操作。

### 5.3 错误文案与外链规则

- 为 HTTP、网络读取、跨域访问及音频初始化或解码失败提供面向用户的反馈。
- HTTP 状态可明确显示，例如“音频文件不存在（HTTP 404）”。
- 浏览器无法准确区分网络与 CORS 原因时，使用“无法获取音频，请检查网络或跨域配置”等合并说明。
- 外部 HTTPS 音频地址需要允许 CORS，以便 `fetch()` 读取响应并创建 Blob。将要求和失败行为写入中英文配置说明。
- 外链读取失败按上述错误流程结束，重试继续使用相同的 Blob 加载路径。
- 音频保留原响应提供的有效 MIME 类型，并使用现有 WAV、MP3、M4A 验证类型识别和浏览器解码行为。

Safari 播放授权被拒绝时，保留已下载资源并进入就绪暂停状态，等待用户点击播放。该状态使用正常歌曲标题和封面。

### 5.4 返回前台与手动重试

- 返回前台时，有效下载仍在进行则继续等待，已完整就绪则根据最新播放意图处理。
- 已经失败的任务显示错误原因及手动“重新加载”入口。
- 手动重试立即执行，清除旧错误并显示加载圈，结果跟随实际任务及最新播放意图。
- 用户暂停、换曲及销毁播放器，分别更新播放意图或取消对应任务。

## 6. 统一播放与进度控制

在现有播放会话内提供明确、可重复调用的播放和暂停操作，并统一提供 `seekTo(seconds)`。

- 网页滑块将百分比转换为秒后调用统一入口。
- Media Session 的 `seekto`、`seekbackward`、`seekforward` 调用同一入口。
- 校验有限数值及有效时长，将目标限制在歌曲有效范围内，结合可跳转范围和实际就绪状态处理跳转。
- 在资源就绪后开放进度调节。
- 拖动过程中保存网页预览值，避免真实进度事件覆盖用户正在拖动的目标。
- 结束拖动和跳转后，以实际音频位置同步界面。
- 切歌时清除旧歌曲的拖动、跳转及异步等待状态。
- 统一处理跳转进行中、完成及失败，防止异步结果影响其他歌曲。

## 7. 完整 Media Session 接入

Media Session 作为浏览器适配层，动作输入调用现有会话，状态输出读取会话及真实音频状态。能力检测集中处理，对不支持的浏览器动作按能力跳过。

接入实现位于现有 `music.ts`。播放会话的快照派生实际已加载曲目，媒体信息按曲目字段变化更新，动作按可用能力变化注册，位置读取持久音频元素的真实时间、时长及倍速。

| 时机 | 处理内容 |
| --- | --- |
| 持久播放器初始化 | 注册支持的播放、暂停、上一首、下一首及进度动作 |
| 实际已加载曲目变化 | 更新标题、作者、封面及可用动作 |
| 歌单长度或其他可用能力变化 | 更新相应动作可用性 |
| 实际播放或暂停变化 | 更新 Playback State |
| 实际位置或有效时长变化 | 更新 Position State |
| 播放器销毁 | 清理处理器、元数据和位置状态 |

动作处理器按生命周期及能力变化更新，进度事件负责位置同步。

切换到另一首歌曲时立即释放旧音频源并清理其位置及元数据，新歌曲初始化就绪后发布新信息。网页标题立即反映当前目标。

单首、空列表、曲目移除、加载失败及恢复时，系统控制能力与网页可用能力保持一致。位置基于实际音频状态，网页拖动预览值用于页面自身交互。

## 8. 原型验证关口

先准备独立的临时验证页，使用现有真实音频和最小交互，验证完整下载、Blob 播放、目标切换、取消及媒体动作。原型结果决定该路线能否进入正式整合。

| 项目 | 通过条件 |
| --- | --- |
| 桌面 Chrome 跳转 | 能定位至指定时间，实际位置在合理解码误差内，避免回到曲首 |
| iPhone Safari 前台 | 下载完成后能够播放、暂停、恢复和调节进度 |
| 播放授权被拒绝 | 保留资源并显示正常封面、标题和播放图标，用户点击后能够继续播放 |
| iPhone 锁屏及其他应用前台 | 当前歌曲继续播放，恢复页面后状态一致 |
| iPhone 后台预取及自然切歌 | 当前曲播放期间完成下一首预取，真实结束事件后命中候选、初始化并实际播放 |
| 下一首尚未就绪 | 显示深蓝底加载圈并继续有效任务，就绪后按最新播放意图处理，失败时反馈原因 |
| 快速切歌 | 最新目标立即生效，已切离歌曲的旧 Blob 及时释放，过期任务结果无法覆盖新目标 |
| 下载期间暂停 | 下载完成后保持暂停，恢复时复用资源 |
| 资源释放 | 请求与计时得到取消，旧 URL 得到撤销，应用及音频元素解除旧引用，多轮切歌后资源趋势稳定 |
| 格式覆盖 | 现有 WAV、MP3、M4A 均通过加载、播放和跳转验证 |

iPhone 后台预取及自然切歌作为关键验收项。使用真实歌曲结束事件触发下一首，分别记录预取是否在当前曲播放期间完成、媒体是否就绪及 `play()` 的结果。返回前台遵循第 5.4 节的有效任务及手动重试规则。

若关键项目失败，先归因至后台 JavaScript 调度、网络任务、媒体初始化或播放授权，再针对失败环节讨论修订。原型结果记录实际设备、Safari 版本、网络条件、前后台操作和事件时序。用户当前提供的测试环境为 iPhone、iOS 26.5.1 Safari，版本以实机确认结果为准。

WebKit 文档说明了用户操作与媒体播放授权之间的关系，具体结果需要结合当前设备实测。[WebKit 说明](https://webkit.org/blog/6784/new-video-policies-for-ios/)

## 11. 原生 URL 播放对照进展

用户确认继续对照后，技术原型已更新为 v3，提供 `/?mode=native` 与 `/?mode=blob` 两个入口。两种模式使用同一文件、同一临时服务和相同等待参数，预取默认关闭，导出记录包含页面与服务端时序。

## 12. 持续传输限速对照进展

用户确认继续后，原型更新为 v4，默认响应前等待为 0、完整传输目标为 40000ms，预取关闭。两种模式共用音频转发，首段真实音频到达后立即写入，随后分段持续限速。JSON 导出记录首段、约每 5 秒累计字节、断开和完整响应时序。测试入口继续使用 Tailscale 的 18766 端口。

桌面 HTTP 客户端对约 20.8 MB WAV 的检查显示，约 275ms 收到首段，随后约 40.01 秒完整读完。两种浏览器播放路径均完成真实结束后的下一首播放，原生路径在持续传输期间开始出声，Blob 路径在完整读取后开始出声。原生样本实际完整传输约 51.9 秒，Blob 样本约 40.0 秒，实际耗时以服务及客户端记录核对。具体实现、校验与操作步骤见原型 README 和 VALIDATION。
