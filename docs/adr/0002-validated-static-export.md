# 0002：导出经过检查的源码包与静态站点包

早期手工 ZIP 缺少统一的发布边界，主题使用者又分别需要可配置源码和可直接托管的站点。2026-10-19 至 20 日将导出固定为一个脚本：先检查并构建，再生成两种带版本、提交短哈希及可选 `-dirty` 标记的 `.tar.gz`，以避免把临时工作目录当作正式交付物。

[tools/export.mjs](../../tools/export.mjs) 使用明确的源码范围和 Git 忽略规则；源码包保留外层主题目录，站点包直接放置网站根文件。未提交且未被忽略的源码也可进入包，已从工作区删除的跟踪文件会被排除；`public/` 中被忽略的资源不会进入站点包。后续发布工具与源码导出复用[文件范围定义](../../tools/lib/publish-files.mjs)。

这个选择要求导出环境具备 Git 和 tar，并要求作者在分享源码包前检查其中的文章和资源；源码包本来就包含选定范围内的 Markdown，不是仅含公开 HTML 的部署产物。运行时部署的产物限制由 [0008](0008-isolated-scheduled-publisher.md) 另行规定。

依据：[S04](SOURCES.md#s04) L15 导出流程需求、L212 双包实现报告；提交 `50dcbb1`，删除文件兼容修复见 `672624d`，共享范围调整见 `862d7b8`。操作说明见[导出发布包](../zh-CN/README.md#导出发布包)。

2026-10-29 更新：[0010](0010-shared-public-resource-selection.md) 将站点资源筛选改为与 Publisher 共用、与跟踪状态无关的主题内忽略规则，并在构建前应用。上文的 Git 筛选保留为原实现记录；源码包范围和版本标记继续沿用本决策。
