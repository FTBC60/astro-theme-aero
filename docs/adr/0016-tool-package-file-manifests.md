# 0016：工具目录包的显式文件清单

2026-11-04（America/Los_Angeles）。用户确认 AuthKey 阶段 A 试验后，授权进入阶段 B。单文件不便组织本地依赖，扩展 [ADR-0014](0014-static-embedded-tools.md) 的交付单位为目录包，继续保持静态主题及原 iframe 语法和权限。

## 决定

`![iframe: 名称](./tool/index.html)` 和 `[名称](./tool/index.html)` 共用入口同目录的 `manifest.json` 校验。v1 清单必需 `version`、`files`，并允许可选的布尔字段 `download`。无清单沿用单 HTML，目录包通过 `index.html` 引用并严格校验文件列表。

[tool-package.mjs](../../src/lib/tool-package.mjs) 验证格式、路径大小写、存在性及普通文件类型，拒绝符号链接和源码/清单发布，按入口最终输出目录展开为原 `{ source, target }` 记录。[note-assets.mjs](../../src/lib/note-assets.mjs) 复用文章归属及冲突校验；共享包仍生成各文章副本。没有新增工具注册中心或全站固定路由。

开发服务器补齐资源 MIME，并为明确登记的工具包入口提供目录别名。[编译缓存](../../src/lib/note-compilation.mjs) 当前内部格式为 3，私有计划包含 `toolEntries` 入口集合与 `archives` 归档描述。归档描述保存入口、ZIP 目标和经过校验的清单，成员来源复用附件列表。作者清单为 v1，单条复制附件只有 source/target。

实际浏览器发现 Astro 7 开发服务器会拦截不透明来源 iframe 的经典脚本与样式请求。因此集成通过仅开发时运行的 Vite post configureServer 回调，将已登记包目录中、且精确命中附件计划的静态文件处理放在该检查之前。其他源码、未选文件及普通附件仍经过原有保护；不设置 CORS、不放宽 iframe 权限。此顺序覆盖 Vite 配置重启，需随 Astro 升级保留浏览器回归。

标准 JSON.parse 语义足够。工具入口同目录的 `manifest.json` 保留为构建元数据，不能列入自身的 `files`。直接引用与 `index.html` 同目录的控制清单作为附件时会报错。子目录 `data/manifest.json` 等资源可以显式列入清单，其他没有相邻 `index.html` 的同名 JSON 按普通附件处理。既有发布器通过完整构建排除旧资源。

## 命名规范化（2026-11-09）

当前约定采用 `manifest.json`、`![iframe: 名称](路径)` 和 `src/content/posts/`，Astro 内部内容集合键也统一为 `posts`。独立工具构建器、引用笔记、示例和使用说明采用相同命名。清单保留范围收缩到入口同目录，回归覆盖根清单拦截、嵌套清单资源、普通 JSON 附件与开发预览的 JSON 响应。

本次本地验收使用 Node.js 22.18.0。串行测试套件 131 项全部通过，Astro 检查 83 个文件且错误、警告、提示均为零，默认站点构建 8 页。四工具在隔离 Vault 中通过真实 Publisher 的 `build-only`，清单内文件与发布副本逐字节一致。Chrome 148 的四工具 iframe 检查全部通过，AuthKey SQLite 引擎初始化正常。重新生成工具后，27 个运行文件及许可证的 SHA-256 与迁移前一致。

## 取舍与验证

### 普通链接目录包（2026-11-09）

普通链接对本地 `index.html` 调用同一清单展开模块，其他 HTML 按单文件交付。查询参数与锚点用于打开页面，清单发现和附件映射使用文件路径。混用 iframe、行内链接及引用式链接时，通过原附件计划去重并执行冲突检查，包入口继续登记到现有开发预览别名集合。

已发布本地 HTML 链接使用新标签页原生导航，保留 Markdown 标题与行内格式，并设置 `rel="noopener"` 和 `data-astro-reload`。页面以站点正常来源运行。浏览器实测覆盖 Worker、fetch、localStorage 以及继续浏览博客后的工具页面状态保留。

本次本地验收共 133 项自动测试通过，6 组浏览器检查和 5 项开发预览更新检查通过，83 文件类型检查零错误、警告和提示，默认站点构建 8 页。完整步骤、环境和本地验证范围见[普通链接目录包验收](../../tools/test/validation-docs/linked-tool-packages-2026-11-09.md)。

### 下载与归档（2026-11-09）

单 HTML 自动提供原文件下载，目录包通过 `download: true` 开启 ZIP。省略字段或设置为 false 时继续发布在线文件。iframe 下载入口位于框架上方，普通链接下载入口紧随原链接。文案复用站点国际化配置。

工具包展开返回已验证文件与清单。归档生成和界面使用同一结果，ZIP 目标加入现有冲突表。构建与开发预览共用 `createToolArchive`，采用锁定的构建依赖 fflate 0.8.2。归档包含所选文件与入口控制清单，全部保留原字节，成员路径保留包内相对关系。生成前核对控制清单与计划一致，归档条目使用固定时间与顺序。

开发预览按请求生成 ZIP，内容同步更新归档计划。完整构建负责归档新增、减项、下载关闭与撤稿清理。实现与复现步骤见[下载归档验收](../../tools/test/validation-docs/tool-downloads-2026-11-09.md)。

本轮 138 项自动测试、7 组浏览器检查和 9 项开发更新检查通过。实际下载的 8 个文件由 Python 标准库独立验证，资源与控制清单原字节匹配，解压后的本地 HTTP 运行也通过。默认站点构建 8 页，84 文件类型检查零错误、警告和提示。

清单遗漏动态依赖仍可能导致工具运行失败，独立浏览器/业务测试承担这项验证；正式发布容器不安装浏览器。原 sandbox 对 fetch、WASM 和存储的限制不变，工具必须自行适配。

使用可复制的中英文时间戳样本验证文件交付和客户端运行，AuthKey 移植保持独立。阶段 B 当时的本地验证及待验范围见[验收记录](../../tools/test/validation-docs/tool-packages-phase-b-2026-11-04.md)。2026-11-09 用户确认四个工具已放入 Obsidian Vault，完成编译、博客实装与阶段 D 验收。该部署状态来源于用户反馈。
