# 0008：将发布容器作为独立编译工具

2026-10-25 至 27 日需要在 NAS 定时发布日记。初版把主题放进镜像，真实使用中修改配置和音乐后仍需重建镜像；用户因此明确，容器只应提供编译工具，每次任务读取外部主题、配置、图片和歌单。只有依赖清单、锁文件或发布工具变化时才重建镜像。

`862d7b8` 的 [Dockerfile](../../Dockerfile) 固定工具链与依赖，主题只读挂载到默认 `/theme`，Vault 挂载到 `notesDir` 对应位置，`/data` 保存工作副本、日志和状态。[手动 CLI](../../tools/deploy.mjs) 与 [Supercronic 调度器](../../tools/scheduler.mjs)调用相同的[发布流程](../../tools/lib/publisher.mjs)：获取共享目录锁，核对主题与镜像依赖一致性，复制主题及笔记，在独立副本检查和构建，通过产物检查后才执行 Wrangler 上传。任务不写原始笔记和主题，也不在挂载目录安装依赖。

该流程以额外复制与检查成本换取任务隔离和可定位的失败状态。笔记复制前后比对指纹并有限重试，不等于文件系统原子快照；锁协调共享同一数据目录的任务，不是跨所有发布设备的远程锁。`site/` 是最近检查通过的候选产物，可能没有成功上线；只有真实发布成功才更新 `last-success.json`。失败或 dry run 不覆盖该成功记录。

定时器在 NAS 容器内运行，Cloudflare 负责接收和托管静态产物，没有新增 Cloudflare Cron 运行端。构建或配置检查失败不上传，部署失败返回失败状态；调度器继续等待下一次计划。具体命令与状态语义见[部署指南](../zh-CN/DEPLOYMENT.md)。
