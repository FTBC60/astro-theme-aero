# 0011：先筛选发布许可，再校验和编译文章

2026-10-29（America/Los_Angeles）决定补充 [0005](0005-explicit-publication.md) 的接入契约：完整 Obsidian Vault 包含没有文章标题、日期或发布属性的私人笔记，要求这些笔记通过文章 Schema 会阻断合法文章的发布。保留显式发布原则，仅让成功解析后顶层小写 `publish` 等于布尔值 `true` 的笔记进入 ID 生成、去重、元数据校验、正文编译和附件收集；其他笔记不进入内容集合，也不以私人 ID 或无效附件干扰已发布文章。

发布值遵循现有 YAML Core 解析：`true`、`True`、`TRUE` 均获得许可；带引号的字符串、数字 `1`、字符串 `yes`、大写字段 `Publish`、缺失字段及布尔假值均不获得许可。不引入原始文本拼写检查。Loader 和 Markdown 文章互链共用 [note-publication.mjs](../../src/lib/note-publication.mjs)，避免两条路径对发布资格作不同判断。

不再校验可解析的未发布笔记，但 Frontmatter 损坏时仍让本轮任务失败并报告文件路径。笔记开头使用 `---` 或 `+++` 却没有结束分隔符，也视为不完整 Frontmatter。无法可靠确定损坏笔记的发布意图，静默跳过可能让线上出现无意撤稿或不完整版本；代价是损坏的私人 Frontmatter 仍会阻断本轮发布。失败不会替换上次完整内容集合或附件清单，Publisher 也不会调用上传步骤。

已发布文章继续要求合法的 `title/date`，保留 URL、排序、附件路径和隐藏目录规则。撤稿在下一次成功的完整构建、部署后生效；本阶段不改变同步器、NAS 挂载、源文件快照策略或 Cloudflare 入口设置。

依据：用户本轮明确接受“先筛选、后编译、再发布”，并修正为接受 YAML 的三种布尔真值。验证覆盖发布值矩阵、私人笔记与 ID 隔离、解析错误，以及真实隔离构建中的附件、撤稿和失败阻断；云端上传使用替身。NAS、实际同步与线上旧 URL 的验收仍另行执行。

2026-10-30 用户复验：已将包含发布筛选与编译完整性改进的代码同步到 NAS 并测试发布，反馈发布没有问题。该结果来源为用户实机反馈，补充上述本地验证记录。

2026-11-01 的 [0012](0012-obsidian-frontmatter-types.md) 明确笔记使用 YAML Core 且不添加隐式时间戳标签，以兼容 Obsidian 去掉日期形状标题/slug 的引号；本篇发布许可及先筛选后校验的契约继续适用。
