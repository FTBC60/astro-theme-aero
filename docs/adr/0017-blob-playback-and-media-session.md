# 0017：完整 Blob 播放、单首预取与 Media Session

2026-11-11（America/Los_Angeles）。扩展 [ADR-0006](0006-runtime-static-playlist.md) 的静态歌单与跨页音频实例。播放器完整下载音频为临时 Blob，在当前歌曲实际播放期间预取下一首，并通过既有会话接入浏览器媒体控制。手动选曲立即执行，资源就绪统一由 `trackStatus` 表达。

## 背景与取舍

本轮对已部署音频的 Range 请求实测得到 `200` 整文件响应。桌面 Chrome 点击网页或浏览器媒体面板的进度条会回到曲首，同一 WAV 在正确处理 Range 的对照中能够跳转。完整下载为 Blob 后，浏览器可对完整资源定位。Worker 音频 Range 路由需要扩展请求处理及 Publisher 配置，选用客户端 Blob 以继续使用现有静态部署流程。研究过程见[开发方案与实施记录](../architecture/music-player-development-plan.md)。

Safari 原型测试进一步表明，前曲结束后才开始长时间下载下一首，后台读取可能中断。当前曲持续播放期间预取的 40 秒慢速样本能够完整下载，并在后台自然衔接下一首。因此采用当前曲加一首候选的资源规则，预取在真实 `playing` 事件后启动。

原设计曾使用可配置的 1 秒手动切歌防抖，并在窗口内保留旧 Blob，以减少连续切歌请求和支持返回旧曲。作者在实际边缘部署中观察到音频通常秒级加载，固定等待带来明显的切歌延迟。最终采用立即选曲及过期任务取消，切换到不同歌曲时立即释放旧资源。

## 决策与资源生命周期

[播放会话](../../src/scripts/playback-session.ts) 继续负责歌曲、播放模式、Blob、候选任务、播放意图、进度和异步结果。[DOM 接入](../../src/scripts/music.ts) 负责界面、浏览器音频适配及 Media Session，歌单浮层沿用既有组件。

- 初次播放完整读取音频响应，创建 Blob URL 并等待音频初始化。资源以原始音频 URL 标识，临时 Blob URL 用于实际播放。
- 会话最多持有当前歌曲及一首候选。候选以在途下载或完整 Blob 保存，实际切入时才创建播放 URL。选曲、模式或歌单变化时复用有效候选，取消无关任务。
- 手动切换立即暂停旧曲、解除音频源并撤销旧 Blob URL，随后消费就绪候选、等待同一在途任务或开始下载。快速切歌以最新目标为准。
- 重新选择当前已就绪歌曲、暂停恢复及单曲循环复用当前资源。切离后返回通过有效候选或重新下载从曲首开始。
- `wantPlaying` 保存用户意图，实际播放状态读取音频元素。下载期间暂停允许有效下载完成，就绪后保持暂停。Safari 拒绝异步播放授权时保留资源，等待用户再次点击。
- `trackStatus` 表达 `idle`、`downloading`、`initializing`、`ready`、`error`。匹配当前 Blob 的 `canplay` 确认初始化完成，就绪判断同时检查资源存在及曲目匹配。
- 下载取消、任务身份核对和播放请求编号分别处理网络取消、过期下载结果及过期 `play()` 结果。音频错误通过 `trackError` 输出，界面从现有状态派生显示。
- Astro 客户端导航复用持久播放器及有效任务。播放器销毁时取消请求和超时、停止音频、解除监听并撤销播放 URL。

加载期间封面显示 Aero 循环加载圈，歌曲进度保持零并禁用调节。完整下载且初始化就绪后，封面约 200ms 淡入，再按最新意图播放或暂停。加载失败时歌名栏显示“加载失败”，歌单底部显示原因，“重新加载”重试对应的歌曲或歌单。返回前台时继续有效任务，失败任务提供手动重试入口。

## 浏览器媒体控制与状态精简

网页和 Media Session 共用会话的播放、暂停、上一首、下一首及 `seekTo(seconds)`。`seekto`、`seekbackward`、`seekforward` 转换为同一按秒跳转入口，结合有效时长和可跳转范围限制目标。

Media Session 元数据跟随实际已就绪歌曲，播放状态和位置取自真实音频元素。动作按浏览器能力及当前可用性注册，元数据按曲目字段变化更新。销毁时清理动作、元数据、播放状态和位置。

本轮精简移除了防抖配置、等待计时器、`waiting` 阶段及旧 Blob 保留分支，同时删除派生快照字段 `playing`、`playbackError` 和重复的 `loaded.ready`。播放结束后的归零集中在播放入口，内部标记清理省去重复状态通知。相关判断继续复用现有会话结构。

## 成本与验证范围

完整下载使首次播放等待整份资源，切离后返回可能再次读取音频，连续选曲也可能产生随后被取消的请求。单首预取增加下载量和候选资源占用。Blob 引用撤销与任务取消限定应用持有的资源，浏览器实际内存回收由运行时管理。外链音频需要允许 CORS，响应的 MIME 类型随 Blob 保留。

2026-11-10 的 Safari 原型样本验证了当前曲持续播放期间后台完成约 40 秒预取，并两次自动衔接下一首。前曲已结束后长时间后台读取仍有失败样本，正式界面按实际错误提供重试。该结果用于选择预取时机，具体系统中断机制仍待证据。

2026-11-11 正式实现及精简后的 30 项会话测试、33 项歌单浮层与触摸测试全部通过，Astro 检查 86 个文件且错误、警告、提示均为零，生产构建通过。原型验证与正式整合的检查分别记录在开发方案中。最终版本的 Chrome 系统控件、跨页续播及 iPhone Safari 整体验收按第 5 阶段安排。
