## 桌面 Chrome 触屏模拟失败与定位

基础触屏轻点在两个部署位置均失败：方向按钮收到正确的 pointerdown/touchstart/pointerup/touchend，但得分仍为 0。独立 HTML 轻点通过；原始主题和无主题的 480px sandbox iframe 对照均失败。直接 CDP 触摸与 locator tap 结果一致，不只发生于 Playwright 的 locator 命中过程。

最小失败对照已经缩到：带页面偏移的 480px sandbox iframe，内部一个 `tabindex="0"` 的大区域及其后的普通按钮，滚动后轻点按钮。没有 Astro、游戏引擎或游戏事件处理器，兼容 click 却命中前面的 DIV。移除前置区域的焦点属性、将 iframe 移到坐标原点，或诊断性移除 sandbox 时，对照通过；鼠标点击也通过。当前样本中只在诊断副本移除棋盘的 tabindex 或命中区域也通过；关闭移动模式而保留 touch 仍失败。

按实测，问题集中在本机 Chrome 模拟触屏对偏移 sandbox iframe 的命中处理；**这是依据对照得出的定位范围，尚不能认定为实体 Android 的同一缺陷，也没有证明某个主题补丁能够修复。** 不以移除键盘焦点、关闭 sandbox、加入 `allow-same-origin` 或全局触摸代理作为主题修复。

额外 CDP 手势探针使用浏览器原生触摸输入，分别得到：

| 子步骤 | 根路径 / `/blog/` |
| --- | --- |
| 在棋盘上滑动并合并，得分 4 | 均通过 |
| 在非棋盘区域向下拖动，使 iframe 内部向上滚动 | 均失败；内部 scrollY 保持 347 |
| 内部到达底部后向上拖动，文章接续滚动 | 均通过；文章从 0 滚到 53 |
| iframe 外侧拖动文章 | 均通过 |

内部拖动探针收到非棋盘 MAIN 的触摸事件，未被工具 preventDefault；本轮尚未把这个滚动失败缩到与点击失败同一原因，不能直接合并归因。桌面鼠标滚轮在两个浏览器内均能滚动工具。WebKit 的轻点通过，但其原生手指拖动、真实手机滚动和双指操作仍待验。

阶段 A 的 Windows WebKit 手写长页切换崩溃，本轮真实 Markdown 长文章、懒加载和历史矩阵未复现；没有更改 WebKit、关闭原生过渡或添加 iframe 重建脚本。**不同样本通过不证明历史崩溃已经修复**，也不替代稳定 Safari 或 iOS 复验。
